# API Reference

All authenticated routes live under `/v1` and use database-backed API keys with
scoped permissions.

```http
X-API-Key: <your-api-key>
```

When `USE_AUTH=true` and the `api_keys` table is empty on first boot, core
bootstraps an `admin` key from the `GREENLIGHT_API_KEY` environment variable. Create
replacement keys via `POST /v1/keys/new` and revoke the bootstrap key.

## Path verbs

| Verb       | Paths                                                                | Meaning                                    |
| ---------- | -------------------------------------------------------------------- | ------------------------------------------ |
| **`new`**  | `POST /v1/prompts/new`, `POST /v1/channels/new`, `POST /v1/keys/new` | Create a **durable resource**              |
| **`send`** | `POST /v1/messages/send`                                             | Deliver **chat text** on a MESSAGE channel |

## Scopes

Middleware checks **any-of** required scopes per route. The `admin` scope grants
all permissions.

| Scope                    | Routes                                                                   |
| ------------------------ | ------------------------------------------------------------------------ |
| `status:read`            | `GET /v1/status`                                                         |
| `keys:read`              | `GET /v1/keys`, `GET /v1/keys/{id}`                                      |
| `keys:write`             | `POST /v1/keys/new`, `DELETE /v1/keys/{id}`                              |
| `prompts:read`           | `GET /v1/prompts`, `GET /v1/prompts/{id}`                                |
| `prompts:write`          | `POST /v1/prompts/new`                                                   |
| `messages:read`          | `GET /v1/messages`, `GET /v1/messages/{id}`                              |
| `messages:send`          | `POST /v1/messages/send`                                                 |
| `channels:read`          | `GET /v1/channels`                                                       |
| `channels:write`         | `POST /v1/channels/new`, `PATCH/DELETE /v1/channels/{id}`                |
| `broadcast_groups:read`  | `GET /v1/broadcast-groups`, `GET /v1/broadcast-groups/{id}` (Enterprise) |
| `broadcast_groups:write` | `POST/PATCH/DELETE /v1/broadcast-groups*` (Enterprise)                   |
| `broadcast_batches:read` | `GET /v1/broadcast-batches/{id}`                                         |
| `audit_log:read`         | `GET /v1/audit-log`, `GET /v1/audit-log/export` (Enterprise)             |
| `settings:read`          | `GET /v1/settings`                                                       |
| `settings:write`         | `PATCH /v1/settings`                                                     |
| `admin`                  | All of the above                                                         |

**Presets** (for `POST /v1/keys/new`):

- `admin` → `['admin']`
- `agent` → prompts, messages, channels read+write (no settings/keys/status/broadcast group scopes)
- `readonly` → all `*:read` scopes including `status:read` (no `broadcast_groups:*` or `broadcast_batches:read`)

## `GET /v1/status`

Deep health for operators and the Admin UI dashboard.

### Response `200`

```json
{
  "status": "ok",
  "database": "ok",
  "channels_active": 2,
  "prompts_pending": 1,
  "prompts_answered_24h": 4,
  "platforms": {
    "telegram": 1,
    "slack": 1
  }
}
```

## `GET /v1/settings` / `PATCH /v1/settings`

Data retention configuration. PATCH body uses the same fields as the GET
response (except `updated_at` is ignored). Days must be 1–3650 when the
corresponding toggle is enabled.

## `POST /v1/keys/new`

### Request body

| Field    | Type     | Required | Notes                                        |
| -------- | -------- | -------- | -------------------------------------------- |
| `name`   | string   | Yes      | Display name                                 |
| `preset` | string   | No       | `admin` \| `agent` \| `readonly`             |
| `scopes` | string[] | No       | Custom scopes (required if `preset` omitted) |

### Response `200`

API key metadata plus `key` (plaintext, shown once).

## `POST /v1/prompts/new`

Accepts **`application/json`** or **`multipart/form-data`**.

Provide **exactly one** send target: `channel_id`, `broadcast_group_id` (Enterprise),
or inline `broadcast_group` (API only — see [Broadcast Groups](/guides/broadcast-groups)).

### JSON body

| Field                | Type     | Required    | Notes                                                            |
| -------------------- | -------- | ----------- | ---------------------------------------------------------------- |
| `text`               | string   | Yes         | Max 4096                                                         |
| `channel_id`         | string   | Conditional | Single-channel send; or `DEFAULT_PROMPT_CHANNEL_ID` when omitted |
| `broadcast_group`    | object   | Conditional | Inline fan-out: `channel_ids` + `prompt_answer_mode` (API only)  |
| `broadcast_group_id` | string   | Conditional | Enterprise: saved broadcast group (`brg_…`)                      |
| `options`            | string[] | No          | Max 10 (3 on WhatsApp/Messenger)                                 |
| `allow_text`         | boolean  | No          | Default `false`                                                  |
| `callback_url`       | string   | No          | Validated HTTP(S)                                                |
| `correlation_id`     | string   | No          | Max 255                                                          |
| `callback_data`      | object   | No          | JSON workflow state (max 8192 bytes), echoed in answer callback  |
| `callback_headers`   | object   | No          | Outbound HTTP headers (max 4096 bytes); not returned on GET      |
| `ttl_sec`            | int      | No          | Default `3600`, max 604800                                       |
| `media_url`          | string   | No          | Mutually exclusive media sources                                 |
| `media_path`         | string   | No          | Under `MEDIA_ALLOWED_DIR`                                        |

Inline `broadcast_group` for prompts:

```json
{
  "channel_ids": ["slack-ops", "telegram-alerts"],
  "prompt_answer_mode": "first_answer"
}
```

`prompt_answer_mode`: `first_answer` \| `all_answer_same` \| `all_answer_majority`.

### Multipart form

Same fields as form parts. Send attachments as `file`. `options` may be a JSON
string. Do not combine `file` and `media_url`.

### Response `200`

Single channel:

```json
{
  "prompt_id": "#123",
  "channel_id": "my-telegram-prompts",
  "message_id": 456
}
```

Multi-channel fan-out:

```json
{
  "broadcast_batch_id": "brd_abc123",
  "channels": [
    { "channel_id": "slack-ops", "prompt_id": "#1", "message_id": "uuid-1" },
    { "channel_id": "telegram-alerts", "prompt_id": "#2", "message_id": "uuid-2" }
  ]
}
```

Each prompt row stores `broadcast_batch_id`, optional `broadcast_group_id`,
snapshotted `broadcast_answer_mode`, and `broadcast_batch_status` (`COLLECTING` at
create). Community rejects `broadcast_group_id` (Enterprise license required).

## `GET /v1/prompts`

### Query

| Param                | Type   | Default   | Notes                                         |
| -------------------- | ------ | --------- | --------------------------------------------- |
| `state`              | string | `pending` | `pending` \| `answered` \| `expired` \| `all` |
| `limit`              | int    | `50`      | 1–200                                         |
| `channel_id`         | string | —         | Filter to one PROMPT channel                  |
| `broadcast_batch_id` | string | —         | Rows from one fan-out batch (`brd_…`)         |
| `broadcast_group_id` | string | —         | Enterprise: filter by saved group (`brg_…`)   |

## `GET /v1/prompts/{id}`

Returns prompt state including `answer`, timestamps, options, and broadcast fields
(`broadcast_batch_id`, `broadcast_group_id`, `broadcast_answer_mode`,
`broadcast_batch_status`). Encode `#` as `%23`. Query `channel_id` is required.

## `PATCH /v1/channels/{id}`

Path `id` is the channel slug (`channel_id` from create).

Update `target_chat_id`, `credentials`, and/or `callback_url`. Reactivates a
deactivated channel. `platform` and `channel_type` cannot be changed.

### Response `200`

```json
{ "status": "Channel ops-slack updated." }
```

### Query

| Param                | Type   | Default | Notes                             |
| -------------------- | ------ | ------- | --------------------------------- |
| `direction`          | string | `all`   | `inbound` \| `outbound` \| `all`  |
| `channel_id`         | string | —       | Filter by channel                 |
| `broadcast_batch_id` | string | —       | Rows from one fan-out batch       |
| `broadcast_group_id` | string | —       | Enterprise: filter by saved group |

## `GET /v1/messages/{id}`

Returns a single message record by UUID.

## `POST /v1/messages/send`

Deliver plain chat text on `MESSAGE` channel(s). Provide **exactly one** target:
`channel_id`, `broadcast_group_id` (Enterprise), or inline `broadcast_group` (API only).

When retention allows, returns the full stored message record (`201`). When zero
retention is enabled, returns `{ "status": "sent", "stored": false, ... }`.

### Request body

| Field                | Type   | Required    | Notes                                           |
| -------------------- | ------ | ----------- | ----------------------------------------------- |
| `text`               | string | Yes         | Message body                                    |
| `channel_id`         | string | Conditional | Single MESSAGE channel                          |
| `broadcast_group`    | object | Conditional | Inline fan-out: `{ "channel_ids": [...] }` only |
| `broadcast_group_id` | string | Conditional | Enterprise: saved message group (`brg_…`)       |

### Response

Single channel: stored message record or `{ "status": "sent", "stored": false }`.

Multi-channel fan-out (`200`):

```json
{
  "broadcast_batch_id": "brd_abc123",
  "channels": [
    { "channel_id": "slack-ops", "message_id": "uuid-1" },
    { "channel_id": "telegram-alerts", "message_id": "uuid-2" }
  ]
}
```

## Broadcast Groups (Enterprise)

Requires Enterprise license with the **broadcast_groups** feature. Community returns
`404` for these routes. Path `{id}` is the group id (`brg_…`).

- **List / create:** `GET` and `POST /v1/broadcast-groups` — query `kind` (`prompt` \| `message`), `limit`; create body: `name`, `kind`, `channel_ids`; `prompt_answer_mode` required for `kind: prompt`.
- **Get / update / delete:** `GET`, `PATCH`, `DELETE /v1/broadcast-groups/{id}`.

See [Broadcast Groups](/guides/broadcast-groups) for examples and edition scope.

## `GET /v1/broadcast-batches/{id}`

Path `{id}` is the batch id (`brd_…`). Returns batch summary plus per-channel `prompts` and `messages` arrays. Prompt
batches include `broadcast_batch_status` (`COLLECTING`, `RESOLVED`, `CONFLICT`,
`EXPIRED`).

## Audit log (Enterprise)

Requires Enterprise license with the **audit_log** feature and `audit_log:read` scope.

### `GET /v1/audit-log`

Query: `limit` (1–200), `cursor`, `action`, `actor_id`, `resource_type`. Returns
`{ "events": [...], "next_cursor": "..." }`.

### `GET /v1/audit-log/export`

Query: `format` (`jsonl` \| `csv`), `action`, `actor_id`, `resource_type`. Downloads
audit events as JSONL or CSV.

## Common errors

| Status | `detail` example                                |
| ------ | ----------------------------------------------- |
| 400    | Validation / missing `callback_url` for MESSAGE |
| 401    | Invalid or missing API key                      |
| 403    | Missing required scope                          |
| 404    | Prompt or channel not found                     |
| 409    | Channel already exists                          |
| 500    | Unexpected server error                         |
