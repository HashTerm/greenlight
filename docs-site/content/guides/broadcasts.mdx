# Broadcast Groups (Enterprise)

**Broadcast groups** are saved sets of channels used for repeated multi-channel sends.
Enterprise license with the **broadcast** feature is required for group CRUD, group-scoped
sends, and the admin **Broadcast Groups** UI.

Community edition can still fan out without a saved group using the inline `broadcast_group`
object on send APIs (API only — not in the web UI). See [Prompts](/guides/prompts).

## Edition and UI scope

| Capability | Community | Enterprise |
| ---------- | --------- | ---------- |
| Inline `broadcast_group` on `POST /v1/prompts/new` and `POST /v1/messages/send` | Yes — **API only** | Yes — **API only** (not in web UI) |
| Saved groups (`broadcast_groups`, `brg_…`) + CRUD API | No (`404`) | Yes |
| Send via `broadcast_group_id` | No | Yes |
| Admin **Broadcast Groups** UI | No | Yes |
| New Prompt / New Message UI | Single `channel_id` only | Single channel **or** saved group |

Neither community nor enterprise web UI submits inline `broadcast_group` — only
`channel_id` or `broadcast_group_id` from forms.

## Concepts

| Concept | Field | ID prefix | Notes |
| ------- | ----- | --------- | ----- |
| **Broadcast group** | `broadcast_group_id` | `brg_…` | Persistent named channel collection |
| **Fan-out batch** | `broadcast_batch_id` | `brd_…` | Links rows created in one API call |
| **Batch status** | `broadcast_batch_status` | — | `COLLECTING`, `RESOLVED`, `CONFLICT`, `EXPIRED` (prompt batches) |

A send to a saved broadcast group sets **both** `broadcast_batch_id` and `broadcast_group_id` on each
prompt or message row.

## Prompt answer modes (prompt groups)

Saved prompt groups require `prompt_answer_mode`:

| Value | Behavior |
| ----- | -------- |
| `first_answer` | First channel answer closes the batch |
| `all_answer_same` | All channels must answer; unanimous required |
| `all_answer_majority` | Strict majority closes remaining channels |

Mode is snapshotted on each prompt row as `broadcast_answer_mode` at send time.

## Broadcast groups API

```http
GET /v1/broadcast-groups
POST /v1/broadcast-groups
GET /v1/broadcast-groups/{broadcast_group_id}
PATCH /v1/broadcast-groups/{broadcast_group_id}
DELETE /v1/broadcast-groups/{broadcast_group_id}
```

Create example (prompt group):

```json
{
  "name": "Ops prompts",
  "kind": "prompt",
  "channel_ids": ["slack-ops", "telegram-alerts"],
  "prompt_answer_mode": "first_answer"
}
```

`kind` must match channel types: `message` → `MESSAGE` channels, `prompt` → `PROMPT`
channels.

## Send via saved group

Use `broadcast_group_id` on the normal send endpoints (exactly one target mode):

```http
POST /v1/messages/send
```

```json
{
  "broadcast_group_id": "brg_…",
  "text": "Deploy finished successfully."
}
```

```http
POST /v1/prompts/new
```

```json
{
  "broadcast_group_id": "brg_…",
  "text": "Approve deploy?",
  "options": ["Approve", "Reject"]
}
```

Multi-channel responses include a shared `broadcast_batch_id` and per-channel ids.

## API-only inline fan-out

Without a saved group, send to multiple channels with inline `broadcast_group` (min 1, max 50 channels):

```json
{
  "broadcast_group": {
    "channel_ids": ["slack-ops", "telegram-alerts"],
    "prompt_answer_mode": "first_answer"
  },
  "text": "Approve deploy?",
  "options": ["Approve", "Reject"]
}
```

Messages omit `prompt_answer_mode`:

```json
{
  "broadcast_group": {
    "channel_ids": ["slack-ops", "telegram-alerts"]
  },
  "text": "Hello everyone"
}
```

## Fan-out batch detail

```http
GET /v1/broadcast-batches/{broadcast_batch_id}
```

Returns batch summary, per-channel prompts or messages, and `broadcast_batch_status` for prompt batches.

## List filters

```http
GET /v1/prompts?broadcast_batch_id=brd_…
GET /v1/prompts?broadcast_group_id=brg_…   # enterprise license
GET /v1/messages?broadcast_batch_id=brd_…
```
