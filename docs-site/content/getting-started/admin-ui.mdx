# Admin UI

The optional **greenlight-ui** Next.js app manages prompts, messages, and
channels plus dashboard stats. Enterprise adds broadcast groups, audit log, and
settings. It talks to the core API server-side with a scoped
`X-API-Key` (`GREENLIGHT_API_KEY`).

**Community self-host:** one super admin account created at `/setup`; no org
switcher and no additional human users in the open-source UI today. Enterprise
and Cloud add multi-user and organization models — see
[Editions & admin identity](/getting-started/editions).

## First-time setup

1. Start the stack (`npm run dev` or `npm run docker:full`)
2. Open **http://localhost:3001/setup**
3. Create the super admin (email + password, min 8 characters)
4. Sign in at **/login**

If `/setup` redirects to `/login` and you never created an account, reset:

```bash
docker exec greenlight-dev-postgres psql -U greenlight -d greenlight \
  -c "DELETE FROM admin_users;"
```

Then visit `/setup` again.

## Pages

| Path         | Purpose                              |
| ------------ | ------------------------------------ |
| `/setup`     | First-run admin creation             |
| `/login`     | Sign in                              |
| `/dashboard` | Health and prompt stats              |
| `/prompts`   | Create prompts and view history      |
| `/messages`  | MESSAGE channel history and send     |
| `/channels`  | Register / list / delete channels    |
| `/broadcast-groups`| Broadcast groups (Enterprise)        |
| `/audit-log` | Audit log (Enterprise)               |
| `/settings`  | Connectivity, retention, and account |

## Register a channel in the UI

1. Go to **Channels → Add channel**
2. Choose platform and channel type (`PROMPT` or `MESSAGE`)
3. Enter `channel_id` (stable slug), `target_chat_id`, and credentials
4. For `MESSAGE` channels, set a reachable `callback_url`
5. Save — the channel detail page shows the webhook URL

Webhook pattern:

```
{PUBLIC_WEBHOOK_URL}/webhooks/{organization_id}/{platform}/{channel_id}
```

## Create a prompt in the UI

**Community:** **Prompts → New prompt** — pick one `PROMPT` channel only.

**Enterprise:** pick one `PROMPT` channel **or** a saved **prompt** broadcast group
from the dropdown (answer mode comes from the group — not chosen on send).

1. Enter text and optional button options
2. Optionally set `callback_url`, TTL, and allow free-text replies

Multi-channel inline fan-out is **API only** — not available in the web UI.
See [Broadcast Groups](/guides/broadcast-groups).

## Send a message in the UI

**Community:** **Messages → Send message** — pick one `MESSAGE` channel only.

**Enterprise:** single channel, or **Broadcast Groups** → message group detail →
**Send message** (pre-selected group).

1. Enter text and submit

Inbound chat on MESSAGE channels is also stored automatically. See
[Messages](/guides/messages).

## Data retention

Under **Settings → Data retention**:

**Scheduled deletion** — enable separately for prompts, inbound messages, and
outbound messages; each has its own day count when enabled.

**Do not store** — skip persisting inbound or outbound messages entirely (zero
retention).

Defaults: prompts scheduled deletion off; inbound and outbound scheduled
deletion on for 30 days; zero retention off for both directions.

## Required env vars for the UI

| Variable             | Purpose                                                                      |
| -------------------- | ---------------------------------------------------------------------------- |
| `DATABASE_URL`       | Same Postgres as core (admin users table)                                    |
| `GREENLIGHT_API_URL` | Core base URL (default `http://localhost:8100`)                              |
| `GREENLIGHT_API_KEY` | Calls core API (`X-API-Key`) — admin-scoped key (bootstrap or from Settings) |
| `AUTH_SECRET`        | NextAuth sessions                                                            |

For hybrid `npm run dev`, set `GREENLIGHT_API_KEY` in the root `.env`. Core and UI use the same value.

See [Configuration](/self-hosting/configuration) for the full list.

## API-only deployments

You can omit the UI entirely. See [API-only mode](/self-hosting/api-only).
